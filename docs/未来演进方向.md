## 0.1 可靠性复盘（2026-09-24 大盘大跌 → 推荐失效）

### 事实

| 项 | 内容 |
| --- | --- |
| 触发日 | 2026-09-24（上一交易日收盘：上证 −1.22%、深成 −2.34%、创业板 −2.68%、沪深300 −1.73%） |
| 现象 | 09-23 尾盘 / 次日开盘买入的推荐票，09-24 **几乎全部跟跌**，T+1 实盘显著负收益 |
| 用户结论 | 「当前算法可靠性存疑」——不再把「高分精选」当可执行信号，先修风控 |

### 根因（算法层，非数据故障）

1. **无大盘 beta 闸门**：六层漏斗只看个股动量 / 板块 / 隔夜美股，**不看当日 A 股指数**。系统性下跌日，涨幅榜本身就是「跌得少 / 抗跌幻觉」，技术指标（放量突破、金叉）在抛售潮里会被误读成「突破」。
2. **涨停 / 追高偏置**：候选池来自涨幅榜，天然偏好已涨多的票；弱涨停 / 一日游与强主题连板未区分，历史标签「涨停」曾被当作正向证据。
3. **胜率叙事误导**：`stats.t1_win_rate` 在牛市 / 震荡样本上好看，**未按市场 regime（偏多 / 偏空 / 急跌）分层**；样本外遇到急跌日即崩。Wilson 区间已上线，但仍缺「按大盘分桶的胜率」。
4. **执行与回测错位**：回测以收盘价为基准，实盘常在次日开盘接飞刀；急跌日 gap-down 把「账面 T+1」打穿。

### 原则（写进后续所有推荐相关改动）

- **宁缺毋滥**：急跌日可以零推荐；空清单 + 明确提示 > 硬推 5 只跟跌票。
- **先过滤市场，再打分个股**：大盘闸门在漏斗最前，不是打完分再微调。
- **胜率必须带条件**：对外展示默认带「样本数 + Wilson 区间 + 市场环境」；裸「70% 胜率」禁止进 UI 主文案。
- **推荐 ≠ 下单指令**：客户端文案继续强调「关注清单 / 卖出参考」，不暗示自动可执行。

## A. 智能化（让 AI 更懂你）

让 AI 从一次性"打分"升级为持续"陪练"。

### A.1 多步 agent 循环

- 单次 `analyzeWithAI` 拆成 plan → gather → analyze → reflect 四步。
- 中间过程落 `meta`，便于回查"AI 当时为啥这么想"。
- 预计：1–2 天。

### A.2 个性化 prompt（学习用户手动调整）

- `LevelAdjuster` 监听用户手动拖动 / 编辑过的价位，记入 `userAdjustments.jsonl`（按 code 聚合）。
- prompt 注入「用户本周在 X 价位附近反复调整过，请尊重」一类弱约束。
- 预计：半天。

### A.3 本地兜底模型（1.5B 量化）

- llama.cpp / Ollama 跑 1.5B Qwen2.5 / Llama3.2，**仅在低延迟场景**（实时盯盘）使用；
- 高不确定性时（行情剧烈 / 信号冲突）走远端 LLM。
- provider 路由见 `Sources/LLMProvider.swift` —— 已具备，新增 `LocalHTTPProvider` 即可。
- 预计：1 天。
- **智能降级已完成（2026-09-21，ROI #7）**：`Sources/AIDegradeGovernor.swift` 客户端熔断——连败 ≥3 次熔断（10 分钟起步指数翻倍，封顶 60 分钟），429 限流 30 分钟，401/403 鉴权与 402 欠费 24 小时；熔断期内**自动分析直接走规则摘要**（不再每次白等满 70s 超时），手动「立即分析」永远放行（半开试探，成功即清零）；状态条透明展示熔断剩余与连败计数。链路「网关 → 直连 → 规则摘要」不变，本组件只决定要不要发起真请求。本地 1.5B 模型接入（OllamaProvider 之外的 llama.cpp）未做。

### A.4 复盘学习（事后比对 → 调权重）

- 每次 `level` / `posAlert` 事件命中或失效后，写入反馈样本；
- 周日跑一次批量 prompt tuning（few-shot 注入），把"高命中价位提示"的样本挑出来作为模板。
- 预计：2–3 天。
- **标签回测 + 保守自动调权已上线**：`daily_pick` 的 T+1 outcome 按 reasons 标签聚合胜率（`GET /picks` 的 `stats.tags`）；生成新推荐时只使用推荐日之前近 30 天数据，单标签样本 ≥30 才介入，单标签 ±10 分、总调整 ±20 分封顶；调权证据写入 `meta.auto_weight` 供客户端透明展示。

### A.5 A 股池智能推荐（2026-09-21 新增，已完成 v1 + v2；**2026-09-25 起进入可靠性加固期**）

- 从全市场涨幅榜淘「高胜率关注清单」，六层漏斗逐层收敛：
  1. **候选**：东财涨幅榜 Top100（push2delay，剔除 ST / 退市 / 次新 / 一字板 / RSI 超买）
  2. **技术指标**：MACD 金叉 30（零上 +5）/ 多头 10、RSI 健康区 15、放量 20、20 日箱体 15 + 近高 10、均线多头 10、KDJ 金叉 10 / 超买 −10、BOLL 中轨上方 5 / 突破上轨 8、BIAS5 超涨 −8
  3. **板块动量**：候选池行业聚合（强势行业 +15 / 弱势 −10，零新增请求）
  4. **隔夜美股**：腾讯 usDJI / usIXIC 情绪 ±10；纳指跌 >1% 半导体类额外 −15
  5. **消息面**：研报评级上调 +25 / 下调 −20；当日新闻关键词（利好 +5 / 利空 −8，±25 封顶）+ 热度；负向公告标签（减持/问询/立案等）扣分
  6. **AI 精排**：客户端透传配置（密钥不落库），失败降级量化序；综合分 <60 不入选（宁缺毋滥）
- **回测闭环**：T+1 下一交易日先回写，T+5 后续补写；`stats` 以 T+1 胜率为主，T+5 作中线参考；工作日 14:45 生成尾盘纯量化版；胜率附带 Wilson 区间 + sample_size。
- Swift 复盘页推荐卡：Top5 行明确标注“今日尾盘 / 上一交易日推荐”、“目标 T+1”以及“短线 / 中线 / 做T”；做T只用于已有底仓，新买仓仍受 T+1 约束。
- **已落地（2026-09-23）**：服务端 `build_trade_plan(is_limit_up)` —— 已涨停候选强制 `entry_timing="next_session_open" / entry_label="次日开盘" / entry_window="09:30-09:35"`，即使在 14:45-15:00 窗口也不标「今日尾盘」（涨停股 T 日买不进）。Swift「尾盘智能推荐」卡加「**尾盘买进清单**」分区：绿勾段为今日可尾盘买入（`entry_timing == today_close && !is_limit_up`），橙色「次盘新股 · 09:30-09:35」段为已涨停需开盘抢的票；不再让用户把涨停票当尾盘目标。
- **已知缺陷（09-24 暴露，见 §0.1）**：漏斗缺 A 股大盘闸门 → 急跌日仍推动量票；胜率未按 regime 分层。止血与后续见 §A.10–§A.14。
- 接口：`GET /api/v1/picks`、`POST /api/v1/picks/run`（详见服务端 README）。
- **下一步**：不再扩候选池（北交所等），先把可靠性做实；池子「换结构」（§A.12）优先于「扩容量」。

### A.9 买卖点价格区间 + 昨日卖出参考（2026-09-24/25 已完成）

### A.11 可靠性加固二期：信号与市场闸门（2026-09-25 起，**P0–P1**）

1. **涨停强弱分档**
   - 强：主题连板 / 换手充分 / 封单厚 → 保留适度正向（或仅作 entry 约束，不再盲目 +15）
   - 弱：首板一日游 / 高开低走 / 跟风板 → −10〜−15，并打「弱涨停」标签进 meta
   - **已完成（2026-09-25）**：以连板、行业共振、换手率、量比四类可复现证据分 `strong / neutral / weak`；强板仅免扣分，中性 −5，弱板 −12；标签与 `meta.limit_up_strength` 同步透出。
2. **regime 分层胜率**
   - 回测按推荐日大盘均值分桶：偏多（≥+0.8%）/ 震荡 / 偏空（≤−0.8%）/ 急跌（≤−2%）
   - `GET /picks` 的 `stats` 增加 `by_regime`；UI 默认展示「当前环境对应桶」的胜率 + Wilson
   - **已完成（2026-09-25）**：`stats.by_regime` 按偏多 / 震荡 / 偏空 / 急跌聚合 T+1 胜率、均值、样本数与 Wilson 区间；客户端优先展示当前环境桶，旧样本无 regime 时回退总样本。
3. **隔夜→当日联动闸门**
   - 条件：隔夜纳指 ≤−1.5% **且** 当日开盘后 A 股三指数均值 ≤−1.0% → 直接 pause（比单看 A 股更早）
   - **已完成（2026-09-25）**：联动条件在个股打分前短路，暂停原因同时写入 `daily_pick_run` 与 `execute_hint`；与 A 股单独 ≤−2% 闸门并行。
4. **纸面 vs 开盘成交曲线**
   - 同一批 picks 画两条 T+1：收盘基准 vs 次日开盘基准；差距过大时降低「可执行」文案权重
   - **已完成（2026-09-25）**：`stats.execution.curve` 返回最近 20 个推荐日的两条累计曲线；平均执行拖累 ≥0.8 个百分点且样本 ≥5 时，UI 自动显示「仅观察」警告。
5. **截面去市场化（残差动量）**
   - 个股涨幅减去所属指数 / 板块涨幅再进分；避免「大盘跌 −2%、个股跌 −0.5%」被当成强势
   - **已完成（2026-09-25）**：个股涨幅减行业均值形成 `residual_pct`，以 ±10 分封顶进入打分，并参与相对强弱候选配额。

### A.12 可靠性加固三期：候选池与组合约束（**P1–P2**）

> 闸门只能「少推」；池子与组合结构不改，仍会在非急跌日扎堆同主题，一跌全灭。

1. **候选池去动量偏置**
   - 现状：东财涨幅榜 Top100 = 天然追高池
   - 改为多源混合：涨幅榜（动量）+ 相对强弱（个股 − 板块）+ 回调区（BIAS/RSI 健康回踩）各占配额
   - 急跌 / 偏空 regime 下**降低涨幅榜配额**，提高「相对抗跌 / 低 beta」配额
   - **已完成（2026-09-25）**：东财按涨幅与换手双源抓取；动量 / 相对强弱 / 健康回调三类配额，偏空时动量额度由 45 降至 25；来源写入 `meta.pool_sources`。
2. **行业 / 题材集中度上限**
   - Top5 同一 `industry`（或同一板块主题）最多 2 只；超限按分数递补下一行业
   - meta 透出 `concentration: { industry, count }`，UI 可提示「同主题扎堆已截断」
   - **已完成（2026-09-25）**：AI 顺序与量化补位统一执行同行业最多 2 只，第三只自动跳过并跨行业递补；最终计数写入 `meta.concentration`。
3. **个股 beta / 波动约束**
   - 近 60 日对沪深300 / 创业板回归 beta；偏空日优先低 beta，高 beta 额外扣分
   - 与已有 `VolatilityTier`（止损侧）复用波动分档，避免两套口径
   - **已完成（2026-09-25）**：按交易日对齐个股与沪深300收益率，最多取 60 个样本回归 beta；偏空日 beta ≥1.3 扣 15 分，beta ≤0.8 加 6 分，并透出到 `meta.risk.beta_60d`。
4. **流动性地板**
   - 近 20 日日均成交额 / 换手下限；过低票在急跌日极易无量砸盘，直接剔除或大幅降权
   - **已完成（2026-09-25）**：近 20 日有效成交额样本 ≥10 时，日均额 <5000 万元直接剔除；当日换手 <0.5% 同样剔除。上游缺成交额字段时降级为未知，不误杀。
5. **日历硬过滤**
   - 财报披露窗口、解禁、定增缴款、ST/*ST 临界、停牌复牌首日 → 硬剔除（不进 Top，不只扣分）
   - 已有负向公告标签作软扣分；日历类改为硬闸，避免「减持当天仍上榜」
   - **已完成（2026-09-25）**：候选源继续前置剔除 ST/*ST、退市与上市首日；新闻事件新增 7 日防泄漏硬闸，覆盖监管立案、终止上市/退市风险、限售解禁、定增缴款、减持实施进展、停复牌首日及业绩预告首亏/续亏/大幅下修。只识别已经发生或确定落地的措辞，“拟减持/减持计划”仍保留为软扣分，避免关键词误杀；未来日期与窗口外事件不参与历史重跑。命中后同时排除生产清单和影子盘，并落 `daily_pick_exclusion`；`stats.hard_filter_exclusions` 汇总当日原因与数量。
6. **拥挤度 / 短线热度惩罚**
   - 近 5 日累计涨幅过大、换手异常、龙虎榜游资扎堆 → 「拥挤」标签 −N；防止终点站上车
   - **已完成（2026-09-25）**：近 5 日涨幅 ≥25% 硬剔除；≥15% 且换手 ≥20% 或量比 ≥2.5 扣 15 分；单独 ≥12% 扣 8 分并标记「短线拥挤」。

### A.13 可靠性加固四期：执行与过程风控（**P1–P2**）

1. **连亏日熔断（策略级，不只大盘）**
   - 近 N 个推荐日（如 3）组合 T+1 收益均为负 → 次日强制 pause 或只出「观察池」不分「可买」
   - 与 §A.10 大盘闸门正交：大盘不跌但策略连续翻车，同样该停
   - **已完成（2026-09-25）**：最近 3 个已回写推荐日的组合 `t1_real` 均值连续为负时，在任何上游请求前暂停并持久化原因。
2. **盘中二次确认 / 双时段清单**
   - 早盘（如 10:00）出「观察版」，14:45 出「执行版」；若两版大盘 regime 翻转或 Top 重叠率 < 阈值 → 降级文案为「仅观察」
   - 避免早盘情绪一日游后，尾盘清单仍按上午逻辑硬推
   - **已完成（2026-09-25）**：工作日 10:00 起生成早盘快照，14:45 起生成尾盘快照；大盘 regime 翻转或 Top 重合率 <40% 时，`market.confirmation` 标记 `observe_only`，客户端明确降级为「仅观察」。暂停日也落快照，避免调度心跳重复生成。
3. **买入区间失效（开盘校验）**
   - 次日开盘价已跌破 `buy_price_low`（或高开超 `buy_price_high` 过多）→ `previous_picks` / 当日卡标注「买入失效 · 勿追」
   - **已完成（2026-09-25）**：回写次日开盘价时同步校验买区；跌破下界或超上界 2% 以上时写入 `outcome.entry_status` / `entry_status_label`，当日卡与上一次推荐均用红色「买入失效 · 勿追」提示。
   - 与卖点区间并列，形成「买得进 / 买不起 / 别买了」三态
4. **量化序 vs AI 精排分歧降权**
   - AI 把量化 Top 外的票抬进 Top5，或大幅打乱顺序时 → 降置信度 / 减推荐只数；分歧大时宁少推
   - **已完成（2026-09-25）**：AI 只能在量化第一名 5 分以内的近邻候选中微调；超过分差的叙事型提名直接忽略，通过者标记「AI量化共识」。
5. **推荐附带风险预算**
   - 每只给出「若明日大盘 −2%，历史同类票期望亏损」；组合层给出当日风险预算上限（例如组合期望短缺不超过 −X%）
   - **已完成（2026-09-25）**：单票压力损失取「beta × 大盘 −2%」与近 20 日期望短缺的更悲观值；Top5 逐只加入时校验组合平均压力损失不低于 −6%，超预算自动跳过并递补。
6. **手动 Kill Switch + 审计**
   - 设置项「暂停智能推荐」一键生效（写服务端 flag）；所有 pause 原因（大盘 / 连亏 / 手动）落审计日志，复盘可查
   - **已完成（2026-09-26）**：设置页新增「暂停智能推荐（Kill Switch）」并同步 `smartPicksPaused`；服务端在任何行情、新闻、AI 请求前硬短路。`daily_pick_run.pause_source` 保存当天最终暂停来源，`pick_pause_audit` 以 `manual / loss_streak / market_crash / joint_market` 结构化记录原因与时间；`GET /picks` 继续返回空清单及 `market.pause_source`。

### A.14 可靠性加固五期：评估、学习与治理（**P2**）

1. **不只胜率：短缺 / 回撤 / 盈亏比**

   - **已完成（2026-09-25）**：`stats.execution` 增加平均盈利/亏损、最差回撤与最差 10% 真实 T+1 的期望短缺；每只候选的 `meta.risk` 同时透出近 20 日回撤和期望短缺，客户端卡片与总览均展示。
2. **Walk-forward / 防泄漏调权**
   - 现有标签自动调权已要求「只用推荐日之前 30 天」；升级为滚动 walk-forward，并禁止用 T+1 未回写日样本
   - 单标签调权增加「regime 条件」：偏空日有效的标签权重 ≠ 偏多日
   - **已完成（2026-09-25）**：滚动 120 日拆成较早 90 日训练窗 + 最近 30 日验证窗，仅使用推荐日之前已回写的真实成交口径 `outcome.t1_real`；标签总样本 ≥30、验证窗 ≥8、训练窗 ≥12，且两窗胜率差不超过 20 个百分点才允许调权。正向加分使用 Wilson 95% 下界、负向扣分使用上界，置信区间跨 50% 时保持中性；当前 regime 样本达标则使用分环境权重，否则逐标签回退全市场权重。`meta.auto_weight` 透出窗口样本、胜率、Wilson 区间、regime_scope 与方法名，便于复盘审计。
3. **影子盘（Shadow）模式**
   - 新规则默认只记账、不上「可买」徽章，跑满 N 个交易日样本外达标后再晋升
   - 客户端可用角标区分「生产清单」vs「影子实验」
   - **已完成（2026-09-25）**：新增独立 `daily_pick_shadow` 表与 `target-stability-challenger-v1`。未通过生产版 5% 双窗口稳定性门槛、但仍通过流动性、拥挤、回撤/ES、行业集中度与组合压力预算的候选，仅写影子盘，不进入 `daily_pick` 和正式 `picks`。调度回写复用真实执行口径，记录次日开盘/尾盘成本、T+1 收益和盘中净 5% 达标结果；`stats.shadow_experiments` 输出完成交易日、样本、真实胜率及 Wilson 下界、5% 达标率及下界。至少 20 个已完成交易日、30 个样本、真实胜率下界 ≥50%、5% 达标下界 ≥5% 才标记 `qualified`，且仍须人工审查后晋升，禁止自动污染生产规则。影子候选不下发为可买项，因此当前客户端不会误显示为生产清单；统计展示可在滚动监控看板统一接入。
4. **滚动监控看板**
   - 复盘页：近 10/20 日组合曲线、按 regime 着色、连亏计数、闸门触发次数
   - 超出阈值自动写周报「策略健康度」段落（对接已有失效归因周报）
5. **卖出侧可靠性**
   - 动态卖点：结合次日开盘强弱调整 §A.9 卖区；弱开盘收窄上方、强调止损侧
   - 「昨日推荐」增加超时未卖提醒（T+1 尾盘仍持有且跌破卖区下沿）
   - **已完成（2026-09-25）**：上一交易日推荐改用真实执行成本生成净 5% + 0.2% 成本目标，不使用 T+1 收盘价事后反推。次日高开 ≥1.5% 归为 `strong` 并扩展止盈上沿，低开 ≤−1% 归为 `weak`、收窄乐观上沿；另列成本 −3% 风险线，明确与盈利目标分离。跌破风险线输出 `risk_exit`，达到目标输出 `take_profit`，T+1 收盘仍未达目标输出 `t1_timeout`。客户端同步显示动态动作与风险线，不再把风险退出价描述成“盈利5%卖点”。
6. **可复现实验包**
   - 每次 `picks/run` 落 `meta.experiment_id`（规则版本哈希 + 闸门参数）；归档进 §F.5 日文件，便于「那天到底用了哪版规则」追责

完整设计见 [`架构-Rust后端.md`](架构-Rust后端.md)，本节只列要点。

### H.1 为什么必须拆

- 当前 `MarketService.swift`（~600 行）+ `AIService.swift`（~250 行）混了网络 IO / 业务编排 / UI 状态，每次加 §F.1–F.4 都要再嵌更多 HTTP 调用，可维护性递减。
- §G 跨设备（iOS / Watch / Telegram Bot）天然要走 HTTP API，先把后端抽出来省得回头返工。
- §A.3 本地 LLM / §A.3 配套 智能降级 在 Rust 端做更顺手（tokio + tracing + sqlx 都是现成的）。

### H.2 决策（2026-09-18 已敲定）

- **部署模式**：独立服务（NAS / 旧 Mac，监听 `0.0.0.0:8732`）。
- **数据库**：SQLite（rusqlite + sqlx）；想换 PostgreSQL 改连接串即可。
- **迁移节奏**：渐进式 4 阶段（行情 → AI → 数据 → 推送）。

### H.3 模块拆分

```
mojinprince-server/
├── src/
│   ├── main.rs / config.rs / state.rs / error.rs
│   ├── api/           # HTTP 路由（quote / ai / signal / position / settings / ws）
│   ├── service/
│   │   ├── quote/     # sina / tencent / eastmoney / failover
│   │   ├── ai/        # Provider trait / openai / ollama / governor
│   │   └── notify.rs  # WebSocket 推送
│   ├── repo/          # sqlx 数据访问
│   └── model/         # DTO
└── migrations/        # sqlx 迁移
```

### H.4 渐进式路线（每阶段都能回退）

| 阶段 | 范围 | 投入 | 收益 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 行情网关（sina/tencent/eastmoney + failover） | 3–4 天 | 前端减少 ~600 行；failover 更稳 | ✅ 2026-09-19 |
| 2 | AI 网关（Provider + 用量 + 命中率） | 2 天 | 本地 LLM + 降级天然支持 | ✅ 2026-09-20 |
| 3 | 信号 / 持仓 / 设置 落 SQLite + HTTP | 2 天 | 跨设备前置 | ✅ 2026-09-20 |
| 4 | WebSocket 推送 + scheduler + §F 数据接入 | 2–3 天 | 实时性 + 数据接入 | ✅ 2026-09-21（含 §A.5 智能推荐、§F.5 归档导出回放等超出原范围的增益） |
| 5（可选） | 鉴权打开 + iOS / Watch / TG Bot | 3–5 天 | §G 跨设备落地 | 未开始（TG Bot 方案已备好，等 token） |

### H.5 关键技术栈

Actix-web 4 + tokio + reqwest + sqlx + tracing + utoipa（Swagger UI）+ JWT。

### H.6 预期收益

- 前端代码减少 ~1100 行（`MarketService` + `AIService` + `SignalTimeline` 落库部分）
- 后端统一处理 failover / 配额 / 成本 / 命中回测，可观测性显著提升
- §A.3 本地 LLM / §F 数据接入 / §G 跨设备 都从"另起炉灶"变成"加一个 service / 加一个 client"

### H.7 关键风险

- 网络抖动 → 前端保留 5 分钟本地缓存（Quote / Signal）
- SQLite 并发 → WAL 模式 + 写串行化
- 公网鉴权漏掉 → 部署时强制 `BIND_ADDR != 0.0.0.0` 必须同时 `JWT_SECRET != ""`

## I. UI 精细化（让已有能力「读得懂、看得清」）

> **定位**：可靠性冲刺把闸门 / regime / 执行曲线 / 买卖点 / ES·回撤一次性塞进了面板，**算法可信了，界面却挤了**。本节不新增业务能力，只做信息架构、视觉层级与组件治理。
> **原则**：宁少露、分层展开；数字必须带单位与条件；红灯 / 暂停永远压过胜率装饰；与 §0.1「推荐 ≠ 下单指令」文案一致。
> **不做什么**：大改视觉风格、引入第三方 UI 库、为打磨而重写 Charts 渲染管线。

### I.0 现状与痛点（2026-09-25）

| 面 | 现状 | 痛点 |
| --- | --- | --- |
| 精选卡 `picksCard` | 情绪灯 + 二次确认 + regime 胜率 + 真实执行 + 曲线 + 标签 + Top5 行（买/卖区、策略胶囊、ES/DD、学习分）+ 尾盘区 + 昨日卖出 | **首屏信息过载**：一眼找不到「能不能买」；胜率行与执行行字号 8–9pt 挤在一起 |
| 盯盘页 | 指数条 → 持仓 → 止损卡 → OHLC → 分时/逐笔 → 指标 → 价位 → 资讯 | 纵向超长，盘中切 tab 成本高；次要区块与主图同权 |
| 图表 | drawingGroup 已移除（Retina 清晰）；价位脉动 / VWAP / 日 K / 逐笔齐全 | 图例、右侧 level 栏、多开关（逐笔等）缺少统一密度档 |
| 代码结构 | `ContentView.swift` ~4.7k 行单体 | 改一行精选卡易误伤盯盘；无共享字号 / 间距令牌 |

### I.1 精选卡信息架构（**P1∥，优先**）

目标：打开复盘 / 盯盘相关「尾盘智能推荐」时，**3 秒内回答三问**——今日能不能买？买哪几只？买/卖价格在哪？

1. **三层折叠（默认只展 L1）**
   - **L1 决策层**：情绪灯 / 暂停或仅观察提示 / Top5 名称+策略+买区（卖区次要字）
   - **L2 证据层**（点击「详情」或 chevron 展开）：regime 胜率 + Wilson、真实执行、期望短缺、标签胜率、调权说明
   - **L3 审计层**（长按 / 「元数据」）：`pool_sources` / `concentration` / `limit_up_strength` / `experiment_id`（对接 §A.14）
2. **空清单专门态**：暂停日不要混用「暂无数据」灰字；大红灯 + `execute_hint` 全文 + 「为何暂停」一句话（大盘 / 连亏 / 隔夜联动）
3. **行内减噪**：每只默认最多 3 个胶囊（策略 / 入场时机 / 一风险）；ES·DD 收到 tooltip 或展开态；学习分仅 |adj|≥0.5 时显示
4. **可买 / 勿追 / 仅观察** 三态用统一色带（绿 / 红 / 橙），与 §A.13 买入失效、§A.13 二次确认同一语义，避免每行自创文案色
5. **预计**：0.5–1 天（纯 SwiftUI 重组，不改 API）

### I.2 设计令牌（字号 / 间距 / 色阶）

- 抽 `UITokens`（或 `DesignSystem.swift`）：`title / body / meta / micro` 四级字号；`stackTight / stackNormal` 间距；`signalBuy / signalSell / signalPause / signalObserve` 语义色（A 股红涨绿跌与信号色分离，避免「红=涨」和「红=危险」打架）
- 精选卡、组合卡、持仓行、通知角标全部改走令牌，消灭散落的 `size: 8/9/10`
- 预计：半天（先令牌 + 精选卡迁移，其它面顺带）

### I.3 数字可读性（可靠性 UI 专属）

对接 §0.1「裸胜率禁止进主文案」：

1. 胜率默认格式：`偏空日 · 52% [41–63] · n=28`（regime + 点估计 + Wilson + 样本），样本不足时主色降为橙并前置 ⚠️
2. 价格区间：`买 12.30–12.80` / `卖 13.10–13.40` 等宽数字 + 浅底，勿与涨跌幅挤同一 HStack
3. 执行曲线：轴标签、图例「纸面 / 开盘」对比；拖累告警条与曲线同卡，不另起一行散落
4. 预计：0.5 天（多在已有 `picksCard` / `PickExecutionCurveView` 上改）

### I.4 盯盘「盘中密度」模式（**P2**）

- 设置项或标题栏切换：**专注**（仅报价头 + 分时 + 关键价位 + 持仓盈亏）/ **标准**（现状）/ **全量**（含资讯·研报·逐笔）
- 默认盘中「专注」、收盘后「全量」；切换记住到 `AppSettings`
- 与 §E.1 菜单栏小卡互补：小卡 = 极简，专注模式 = 面板内极简
- 预计：1 天

### I.5 图表微交互与图例治理（**P2**）

- 分时 / 日 K / 指标图统一图例条（色点 + 短名），hover 时高亮对应系列、淡化其它
- 右侧 level 栏与价位线：命中 / 等待 / 失效三态图标与精选卡三态色对齐
- 逐笔开关、MA 显隐等收入「图显」菜单，避免分时卡顶部按钮横排膨胀
- 预计：0.5–1 天（`Charts.swift` 局部，不重做 Canvas）

### I.6 组件拆分（工程向，服务精细化）

- 从 `ContentView` 拆出：`PicksCardView` / `WatchHeatmapView` / `PortfolioCardView` / `CodeInfoPanel`（文件级，API 不变）
- 便于单测截图回归（可选 Snapshot）与按面迭代，避免 4.7k 行继续膨胀
- 预计：0.5–1 天；**可与 I.1 同 PR 或紧随其后**

### I.7 主题与对比度（**P3**）

- 已有浅色 / 深色设置；补齐 tertiary 在深色下的对比（现网部分 8pt tertiary 几乎不可读）
- 脉动预警在深色背景上的描边亮度校准（二级红描边勿「糊成一团」）
- 预计：半天

### I.8 键盘与可达性（**P3**）

- §E.3 快捷键已有；补：精选行 ⌘↵ 跳盯盘、Esc 收起 L2/L3 展开
- VoiceOver：情绪灯 / 暂停态提供 `accessibilityLabel`（「大盘跌 2.3%，今日暂停推荐」）
- 预计：半天

### I.9 成功标准（可验收）

1. 暂停日：未展开 L2 时，用户仍能完整读到暂停原因；无「暂无推荐」灰字误导。
2. 有清单日：默认态 Top5 每行不超过 3 个胶囊 + 买区一行；胜率细节需一次点击才出现。
3. 同一语义（可买 / 勿追 / 仅观察 / 暂停）在精选卡、昨日卖出、盯盘提示三处色与文案一致。
4. `ContentView` 精选相关代码迁出独立文件后，改买卖点展示不再 diff 到委托 / 策略 tab。

## G. 跨设备

### G.1 iOS 端同步（CloudKit）

- 用 `NSUbiquitousKeyValueStore` 同步 AppSettings（小配置）；
- `CloudKit` 同步 SignalTimeline / 持仓 / 自选（中数据）。
- iOS 端做只读视图（不能下单）。
- 预计：3–5 天（独立 iOS 项目）。

### G.2 Watch 端镜像

- WatchOS App 显示菜单栏报价 + 关键价位（今日三档线）。
- 抬手即看（避免掏出手机）。
- 预计：2–3 天。

### G.3 Telegram Bot

- BotFather 注册 bot，webhook 接 AlertService。
- 关键预警自动转发到 TG；支持 /quote /analyze /holdings 三个命令。
- 预计：1 天。
- **方案已备好（2026-09-21）**：改走服务端 Rust 模块（`service/telegram.rs`）+ `getUpdates` 长轮询（无需公网 IP / 端口转发，符合无鉴权不出公网的安全边界）；推送（收盘复盘 / 每日推荐 Top5 / 评级信号 / 跌破止损）+ 命令（/quote /picks /holdings /report）；`TELEGRAM_BOT_TOKEN`（env 不进 Git）+ `TELEGRAM_CHAT_ID` 白名单只响应用户本人；token 未配置模块休眠。等用户 BotFather 建 bot 拿 token 后开工。

## 不做什么（保持克制）

- ❌ 自动下单：合规风险 + 用户决策权让渡；继续靠"通知 + 一键跳卖出口袋"。
- ❌ 多账号资产管理 / 跟单：偏离个人工具定位。
- ❌ Web 版 / 移动端：先把 macOS 体验做透（iOS 只读除外）。
- ❌ 第三方数据源再接 N 个：先把 F.1–F.4 吃透。
- ❌ **在可靠性未达标前扩推荐池 / 加推送渠道**：急跌日把坏信号推到 TG / iOS 只会放大损失（09-24 教训）。
- ❌ **用总胜率单独做营销文案**：必须带样本数、Wilson 区间、市场 regime。
- ❌ **为打磨而重做视觉皮肤 / 引入 UI 框架**：§I 只做信息架构与令牌，不换皮肤、不接第三方组件库。
