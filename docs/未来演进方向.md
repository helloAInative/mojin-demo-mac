## A. 智能化（让 AI 更懂你）

让 AI 从一次性"打分"升级为持续"陪练"。

### A.1 多步 agent 循环

- 单次 `analyzeWithAI` 拆成 plan → gather → analyze → reflect 四步。
- 中间过程落 `meta`，便于回查"AI 当时为啥这么想"。
- 预计：1–2 天。

### A.2 个性化 prompt（学习用户手动调整）

- `LevelAdjuster` 监听用户手动拖动 / 编辑过的价位，记入 `userAdjustments.jsonl`（按 code 聚合）。
- prompt 注入「用户本周在 X 价位附近反复调整过，请尊重」一类弱约束。
- 预计：半天。

### A.3 本地兜底模型（1.5B 量化）

- llama.cpp / Ollama 跑 1.5B Qwen2.5 / Llama3.2，**仅在低延迟场景**（实时盯盘）使用；
- 高不确定性时（行情剧烈 / 信号冲突）走远端 LLM。
- provider 路由见 `Sources/LLMProvider.swift` —— 已具备，新增 `LocalHTTPProvider` 即可。
- 预计：1 天。
- **智能降级已完成（2026-09-21，ROI #7）**：`Sources/AIDegradeGovernor.swift` 客户端熔断——连败 ≥3 次熔断（10 分钟起步指数翻倍，封顶 60 分钟），429 限流 30 分钟，401/403 鉴权与 402 欠费 24 小时；熔断期内**自动分析直接走规则摘要**（不再每次白等满 70s 超时），手动「立即分析」永远放行（半开试探，成功即清零）；状态条透明展示熔断剩余与连败计数。链路「网关 → 直连 → 规则摘要」不变，本组件只决定要不要发起真请求。本地 1.5B 模型接入（OllamaProvider 之外的 llama.cpp）未做。

### A.4 复盘学习（事后比对 → 调权重）

- 每次 `level` / `posAlert` 事件命中或失效后，写入反馈样本；
- 周日跑一次批量 prompt tuning（few-shot 注入），把"高命中价位提示"的样本挑出来作为模板。
- 预计：2–3 天。
- **轻量版已上线（推荐标签回测）**：`daily_pick` 的 T+5 outcome 按 reasons 标签聚合胜率（`GET /picks` 的 `stats.tags`），哪个因子有效一目了然；样本 ≥30 后可据此自动调权（下一步）。

### A.5 A 股池智能推荐（2026-09-21 新增，已完成 v1 + v2）

- 从全市场涨幅榜淘「高胜率关注清单」，六层漏斗逐层收敛：
  1. **候选**：东财涨幅榜 Top100（push2delay，剔除 ST / 退市 / 次新 / 一字板 / RSI 超买）
  2. **技术指标**：MACD 金叉 30（零上 +5）/ 多头 10、RSI 健康区 15、放量 20、20 日箱体 15 + 近高 10、均线多头 10、KDJ 金叉 10 / 超买 −10、BOLL 中轨上方 5 / 突破上轨 8、BIAS5 超涨 −8
  3. **板块动量**：候选池行业聚合（强势行业 +15 / 弱势 −10，零新增请求）
  4. **隔夜美股**：腾讯 usDJI / usIXIC 情绪 ±10；纳指跌 >1% 半导体类额外 −15
  5. **消息面**：研报评级上调 +25 / 下调 −20；当日新闻关键词（利好 +5 / 利空 −8，±25 封顶）+ 热度
  6. **AI 精排**：客户端透传配置（密钥不落库），失败降级量化序；综合分 <60 不入选（宁缺毋滥）
- **回测闭环**：T+1 / T+5 收盘价自动回写 `meta.outcome`，`stats` 输出整体胜率 + 标签级胜率；工作日 15:30 后调度器自动生成纯量化版。
- Swift 复盘页推荐卡：Top5 行（标签胶囊 / T+5 回测着色）+ 胜率统计行 + 隔夜纳指 + 「AI 精排」一键触发；行点击自动加「观察」组跳盯盘。
- 接口：`GET /api/v1/picks`、`POST /api/v1/picks/run`（详见服务端 README）。
- **下一步**：样本 ≥30 后按标签胜率自动调权（A.4 联动）；候选池加入北交所 / 融资融券异动。

## B. 走势图进化

从"画得好看"到"画得有信息"。

### B.1 AIEvents 联动 SignalTimeline（右侧栏）

- 把当天发过的所有 `level` 事件按时间戳画到分时图右侧栏（竖列），颜色按 hit / 失效区分。
- 已发出但未到价的事件标"等待中"，已到的标"✓"并标 leadSec。
- 预计：半天。
- **已完成（2026-09-21）**：`MinuteChart.levelMarks` 右侧 20pt 竖栏——`MarketStore.levelMarks` 过滤当日当前标的的 level 事件，按交易时段槽位落位（盘前 / 午休线性夹紧），hit=绿 ✓ + leadSec、6h 外未中=红 ×、窗口内=灰 …；状态分类独立编译 4 项断言验证。

### B.2 多周期叠加（分时 + 日线两层）

- 分时图（96px）+ 日线（288px）上下叠放，共享时间轴。
- 日线层级画 K 线 + MA5/10/20 + 成交量条。
- 预计：1 天。

### B.3 VWAP / 成本均线画入分时图

- VWAP = ∑(典型价 × 成交量) / ∑成交量，按分钟复算。
- 成本均线 = `position.cost` 在分时图上平滑成一条线（与已有"到本"虚线区别）。
- 预计：半天。
- **已完成（2026-09-21）**：均价线（VWAP）以黄细线画入分时图（腾讯分钟数据自带逐分钟 avg，即 VWAP，无需本地复算；hover 亦显示数值）；成本线 `drawCostLine` 早已存在（成本水平线 + 到本闪烁角标），未做"平滑成本均线"（当前水平线语义已够用）。

### B.4 逐笔成交回放（分时下方柱状）

- 数据源：新浪 / 东财 tick 接口；按 1 分钟桶聚合画柱。
- 用户点击柱可下钻查看逐笔。
- 预计：1–2 天。

### B.5 板块联动（板块涨幅叠加）

- 申万一级 / 二级行业指数拉一条线，与个股分时并排对比。
- 当板块涨 / 个股不涨 → 自动产出"个股弱势"提示。
- 预计：1 天。

### B.6 热力图（自选股格子）

- 所有自选股按"涨跌幅 × 量比 × AI 评级"画 4×N 格子热力图。
- 颜色梯度：绿（强）→ 灰（中性）→ 红（弱）。
- 预计：半天。
- **已完成（2026-09-21，涨跌幅维度）**：自选页顶部 4 列格子——名称 + 涨跌幅，A 股红涨绿跌梯度（±3% 封顶，±0.06 中性灰），点击格子跳盯盘；无报价的自选不占格。「量比 × AI 评级」维度未做（watchQuotes 无逐标的量比与 AI 级，等数据齐了再加）。

## C. 决策辅助（让 AI 帮你更快决策）

让 AI 不仅给"价位"，还参与"动作"。

### C.1 AI 反向校验（手动下单后）

- 用户手动提交买单后，调一次 `analyzeWithAI(quick=true)`，输出"建议撤单 / 加仓 / 不动"。
- 弹窗倒计时 30 秒无操作即默认不动（防骚扰）。
- 预计：1 天。

### C.2 回测可视化（命中点打 K 线）

- `StrategyEngine.backtest` 的命中点 / 失效点直接画到日线 K 线图上（▲ / ✕）。
- 鼠标悬停查看"当日 AI 评语 + 命中价位 + 实际涨跌"。
- 预计：半天。

### C.3 AI 提示冷却（同价位反复提示）

- 同一个价位 5 分钟内触发 ≥ 3 次预警 → 自动把后续通知折叠为一条 + 加 "刚才提示过" 标记。
- 视觉上避免"同一价位闪 5 次"。
- 预计：半天。

### C.4 持仓联动：浮盈/浮亏 + AI 减仓建议

- 现价 vs `position.cost` 接近阈值时，弹窗显示「浮盈 ¥X / X %，AI 建议：减仓 30%」。
- AI 建议输出走单独 prompt（更短、更保守），仅展示，不自动下单。
- 预计：1 天。
- **AI 点评止损止盈位已接**：`analyze` prompt 注入三锚点建议数值与依据，AI 只做叙事复核不另给价。

### C.5 智能止损 / 止盈（2026-09-21 新增，已完成 ROI #2）

- `Sources/StopTakeAdvisor.swift` 纯函数：止损取最保守锚（波动 现价−2×ATR14 / 结构 近 20 日低 / 成本回撤 5%），止盈取最近锚（波动 +3×ATR / 结构高点 / 阻力位）；盈亏比 <1.5 或止损距现价 <2% 自动降级为提示，不给一键应用。
- 持仓止盈全链路：`PositionNote.takeProfit`（服务端列早已存在）+ `PUT /positions` 同步 + `linkTakeToAbove` 对称联动到价上；跌破止损 / 触达止盈专属提醒（同价抑制通用到价防双响），通知点击按 side 预填委托草稿。
- 盯盘页建议卡：锚点 tooltip + 手动覆盖标记，一键应用写本地 + 网关并落 `stopTake` 时间线；复盘日报自动做「已成交卖出 vs 止损止盈价」执行对照（偏差金额 + 百分比）。
- **下一步**：锚点参数按个人波动率自适应（当前 k=2 / m=3 / 盈亏比 1.5 固定）。

让用户从"信任感"出发，长期使用。

- 配色规则：≥60% 绿 / 40–60% 橙 / <40% 红。
- 预计：半天。
- **已完成（2026-09-21，命中曲线时序化 / ROI #5）**：AI 页三件套下方新增「命中率曲线 · 近 30 天」——`AccuracyTimeline.build` 按北京时间日历日分桶 level 事件（含空档日），上区 7 日滚动命中率折线（50% 参考线），下区每日信号数柱（命中着色），悬停看单日明细与滚动值；聚合逻辑独立编译 16 项断言验证。"近 20 次窗口"分档未做；「周报导出」已完成（复盘历史一键导出 .md / 复制全文，见服务端 README）。

### D.2 通知审计（发过 → 用户动作）

- `SignalEvent` 已有 `kind` / `meta`，新增 `userAction: pending | dismissed | opened | sold` 字段。

### D.3 误报率自调（连续忽略 → 收紧阈值）

### D.4 健康度面板（成功率 / 耗时 / 失败原因）

- 预计：半天。

### D.5 失效归因周报（2026-09-21 新增，已完成 ROI #9）

- 周报正文新增「失效归因（level 预警）」：本周 level 信号按 `day_bar` 高 / 低判定——命中 / **穿越未确认**（曾到价但 6h 内未回写，多为假突破扫损）/ **未到价**（最近偏离度 + 已过天数，TOP3）/ 窗口未满 / 无日线，另汇总被忽略的 AI 反馈计数；`payload.summary` 带结构化字段。

### F.3 新闻 / 公告接入

- 东方财富 / 同花顺新闻流，按 `code` 聚合。
- AI prompt 注入「近 24h 新闻：…」，作为分析证据。
- 预计：1 天。
- **已完成（2026-09-20，东财全文搜索）**：`GET /api/v1/news/{code}?limit=&hours=` 按需拉取后 UPSERT 落 `news_item` 缓存表，响应按时间窗过滤；`POST /api/v1/ai/analyze` 加 `include_news: true` 时把近 24h 新闻（≤5 条）拼进 prompt（`analyze` 的 `with_recent_news`），拉取失败只 warn 不阻断分析。公告（东财公告接口）与同花顺源未接。

### F.4 研报接入（分析师评级）

- 朝阳永续 / 慧博 / 东财研报库，每日增量拉取。
- 评级作为辅助信号：买入 / 增持 → 提示"机构看多"；反之亦然。
- 预计：1–2 天。
- **已完成（2026-09-20，东财研报库 + 概念板块；09-21 评级信号化 + Swift 展示）**：`GET /api/v1/reports/{code}?limit=&days=` 落 `research_report`（机构 / 评级 / 上次评级 / 评级变动 / 分析师 / 目标价 / 详情页 URL）；`GET /api/v1/sector/{code}` 合并 `RPT_F10_CORETHEME_BOARDTYPE` 成分与 `ulist.np` 批量行情落 `sector_board`；`spawn_ingest_scheduler` 工作日 16:00 后对自选股（≤60 只）增量刷新一次（同日只跑一次）。「机构看多 / 看空」信号化已接：每日刷新时把近 7 天且评级明确的研报写成 `kind=report` 的 `signal_event`（id 由 `(code, info_code)` 派生，幂等不重复），经既有 signals 同步自动到 Swift（`kindLabel`「机构研报」）。Swift 盯盘页已接入「资讯 · 研报 · 板块」面板：板块涨跌色块（主营优先）、研报评级行（点击开详情页）、近 72h 新闻流（点击开原文），切换自选自动加载、失败降级为提示。

### F.5 每日数据归档 / 导出 / 回放（2026-09-21 新增，已完成 ROI #12）

- **自动归档**：报告调度器收盘后把最近已收盘交易日的自选股分时（minute_bar）、收盘快照、当日信号、AI 用量与持仓写成 `{数据库目录}/archives/{date}.json`（同日幂等；周五晚间没开机时周末 / 周一自动补）。
- **导出端点**：`GET /api/v1/export/day?date=` 与归档同构（同一组装函数三处复用），缺省最近已收盘交易日。
- **回放（Swift 复盘页）**：最近 7 日选择 → 归档分时（北京时间 HHmm 转换）喂 MinuteChart 叠加当前关键位 + 当日信号列表；「导出 .json」一键存档完整数据。逐笔 tick 回放仍属 §B.4，不掺入。
- 数据是资产：按日沉淀，出问题能复盘「那天到底发生了什么」。

## H. 架构演进（前后端分离）

为支撑 §F 数据接入、§G 跨设备、以及本地 LLM / 降级等高级能力，单体 macOS App 必然要从「网络 + 业务 + UI 全栈」拆成「前端 UI + 后端服务」。

完整设计见 [`架构-Rust后端.md`](架构-Rust后端.md)，本节只列要点。

### H.1 为什么必须拆

- 当前 `MarketService.swift`（~600 行）+ `AIService.swift`（~250 行）混了网络 IO / 业务编排 / UI 状态，每次加 §F.1–F.4 都要再嵌更多 HTTP 调用，可维护性递减。
- §G 跨设备（iOS / Watch / Telegram Bot）天然要走 HTTP API，先把后端抽出来省得回头返工。
- §A.3 本地 LLM / §A.3 配套 智能降级 在 Rust 端做更顺手（tokio + tracing + sqlx 都是现成的）。

### H.2 决策（2026-09-18 已敲定）

- **部署模式**：独立服务（NAS / 旧 Mac，监听 `0.0.0.0:8732`）。
- **数据库**：SQLite（rusqlite + sqlx）；想换 PostgreSQL 改连接串即可。
- **迁移节奏**：渐进式 4 阶段（行情 → AI → 数据 → 推送）。

### H.3 模块拆分

```
mojinprince-server/
├── src/
│   ├── main.rs / config.rs / state.rs / error.rs
│   ├── api/           # HTTP 路由（quote / ai / signal / position / settings / ws）
│   ├── service/
│   │   ├── quote/     # sina / tencent / eastmoney / failover
│   │   ├── ai/        # Provider trait / openai / ollama / governor
│   │   └── notify.rs  # WebSocket 推送
│   ├── repo/          # sqlx 数据访问
│   └── model/         # DTO
└── migrations/        # sqlx 迁移
```

### H.4 渐进式路线（每阶段都能回退）

| 阶段 | 范围 | 投入 | 收益 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 行情网关（sina/tencent/eastmoney + failover） | 3–4 天 | 前端减少 ~600 行；failover 更稳 | ✅ 2026-09-19 |
| 2 | AI 网关（Provider + 用量 + 命中率） | 2 天 | 本地 LLM + 降级天然支持 | ✅ 2026-09-20 |
| 3 | 信号 / 持仓 / 设置 落 SQLite + HTTP | 2 天 | 跨设备前置 | ✅ 2026-09-20 |
| 4 | WebSocket 推送 + scheduler + §F 数据接入 | 2–3 天 | 实时性 + 数据接入 | ✅ 2026-09-21（含 §A.5 智能推荐、§F.5 归档导出回放等超出原范围的增益） |
| 5（可选） | 鉴权打开 + iOS / Watch / TG Bot | 3–5 天 | §G 跨设备落地 | 未开始 |

### H.5 关键技术栈

Actix-web 4 + tokio + reqwest + sqlx + tracing + utoipa（Swagger UI）+ JWT。

### H.6 预期收益

- 前端代码减少 ~1100 行（`MarketService` + `AIService` + `SignalTimeline` 落库部分）
- 后端统一处理 failover / 配额 / 成本 / 命中回测，可观测性显著提升
- §A.3 本地 LLM / §F 数据接入 / §G 跨设备 都从"另起炉灶"变成"加一个 service / 加一个 client"

### H.7 关键风险

- 网络抖动 → 前端保留 5 分钟本地缓存（Quote / Signal）
- SQLite 并发 → WAL 模式 + 写串行化
- 公网鉴权漏掉 → 部署时强制 `BIND_ADDR != 0.0.0.0` 必须同时 `JWT_SECRET != ""`

## 不做什么（保持克制）
