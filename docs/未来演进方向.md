# 摸金小王子 · 未来演进方向

> 本文按用户视角（A–G 七大类）重新梳理「捷捷微电摸鱼 / 摸金小王子」的下阶段方向。
> 与 [`按ROI排序.md`](按ROI排序.md)（按投入产出比拆解）、[`架构-Rust后端.md`](架构-Rust后端.md)（后端架构）互为正交：本文回答"我想做什么"，ROI 表回答"先做哪个"，架构文档回答"怎么做"。

## 0. 现状锚点（截至 2026-09-18）

最近三轮迭代已完成：

| 维度 | 现状 |
| --- | --- |
| AI 分析 | `AIService.chat` 调用 OpenAI 兼容协议（默认阿里 Token Plan / qwen3.7-plus），输出强制 JSON；`AILatestSignal` 落 `levels / events / volumeWarnRatio / keyPoints / risk` |
| 走势图标记 | MinuteChart / MACDChart / LineTripleChart / VolumeChart 全部支持 AI 价位 ▲▼ + 事件流箭头 + Y/X 轴刻度 + Crosshair hover |
| 价位预警 | 一级 / 二级双档闪烁（默认 0.30 % / 0.15 %，设置面板可调），靠近现价时整条价位线脉动 + 系统通知 |
| 持仓联动 | 成本线 + 「到本」角标；接近 ±1 % 时橙红闪烁 + 系统通知（默认 1 %，可调 0.10–3.00 %）；盯盘页可查看浮盈 / 浮亏详情并一键复制摘要 |
| AI 命中回测 | `SignalEvent.meta` 携带 `hit / leadSec / hitAt`；6 h 内价到自动回写，UI 显示「命中率 / 平均领先 / 最大偏离」三件套 |
| LLM 抽象 | `LLMProvider` 协议 + `ProviderRegistry` 已就位，`AIService.chat` 仍为默认实现（向后兼容） |
| 通知治理 | `NotifyGovernor` 冷却 / 聚合 / 免打扰 / 配额；点击通知 → `pendingUIAction` + `pendingLevelPayload` 直达交易口袋 |

## A. 智能化（让 AI 更懂你）

让 AI 从一次性"打分"升级为持续"陪练"。

### A.1 多步 agent 循环

- 单次 `analyzeWithAI` 拆成 plan → gather → analyze → reflect 四步。
- 中间过程落 `meta`，便于回查"AI 当时为啥这么想"。
- 预计：1–2 天。

### A.2 个性化 prompt（学习用户手动调整）

- `LevelAdjuster` 监听用户手动拖动 / 编辑过的价位，记入 `userAdjustments.jsonl`（按 code 聚合）。
- prompt 注入「用户本周在 X 价位附近反复调整过，请尊重」一类弱约束。
- 预计：半天。

### A.3 本地兜底模型（1.5B 量化）

- llama.cpp / Ollama 跑 1.5B Qwen2.5 / Llama3.2，**仅在低延迟场景**（实时盯盘）使用；
- 高不确定性时（行情剧烈 / 信号冲突）走远端 LLM。
- provider 路由见 `Sources/LLMProvider.swift` —— 已具备，新增 `LocalHTTPProvider` 即可。
- 预计：1 天。

### A.4 复盘学习（事后比对 → 调权重）

- 每次 `level` / `posAlert` 事件命中或失效后，写入反馈样本；
- 周日跑一次批量 prompt tuning（few-shot 注入），把"高命中价位提示"的样本挑出来作为模板。
- 预计：2–3 天。

## B. 走势图进化

从"画得好看"到"画得有信息"。

### B.1 AIEvents 联动 SignalTimeline（右侧栏）

- 把当天发过的所有 `level` 事件按时间戳画到分时图右侧栏（竖列），颜色按 hit / 失效区分。
- 已发出但未到价的事件标"等待中"，已到的标"✓"并标 leadSec。
- 预计：半天。

### B.2 多周期叠加（分时 + 日线两层）

- 分时图（96px）+ 日线（288px）上下叠放，共享时间轴。
- 日线层级画 K 线 + MA5/10/20 + 成交量条。
- 预计：1 天。

### B.3 VWAP / 成本均线画入分时图

- VWAP = ∑(典型价 × 成交量) / ∑成交量，按分钟复算。
- 成本均线 = `position.cost` 在分时图上平滑成一条线（与已有"到本"虚线区别）。
- 预计：半天。

### B.4 逐笔成交回放（分时下方柱状）

- 数据源：新浪 / 东财 tick 接口；按 1 分钟桶聚合画柱。
- 用户点击柱可下钻查看逐笔。
- 预计：1–2 天。

### B.5 板块联动（板块涨幅叠加）

- 申万一级 / 二级行业指数拉一条线，与个股分时并排对比。
- 当板块涨 / 个股不涨 → 自动产出"个股弱势"提示。
- 预计：1 天。

### B.6 热力图（自选股格子）

- 所有自选股按"涨跌幅 × 量比 × AI 评级"画 4×N 格子热力图。
- 颜色梯度：绿（强）→ 灰（中性）→ 红（弱）。
- 预计：半天。

## C. 决策辅助（让 AI 帮你更快决策）

让 AI 不仅给"价位"，还参与"动作"。

### C.1 AI 反向校验（手动下单后）

- 用户手动提交买单后，调一次 `analyzeWithAI(quick=true)`，输出"建议撤单 / 加仓 / 不动"。
- 弹窗倒计时 30 秒无操作即默认不动（防骚扰）。
- 预计：1 天。

### C.2 回测可视化（命中点打 K 线）

- `StrategyEngine.backtest` 的命中点 / 失效点直接画到日线 K 线图上（▲ / ✕）。
- 鼠标悬停查看"当日 AI 评语 + 命中价位 + 实际涨跌"。
- 预计：半天。

### C.3 AI 提示冷却（同价位反复提示）

- 同一个价位 5 分钟内触发 ≥ 3 次预警 → 自动把后续通知折叠为一条 + 加 "刚才提示过" 标记。
- 视觉上避免"同一价位闪 5 次"。
- 预计：半天。

### C.4 持仓联动：浮盈/浮亏 + AI 减仓建议

- 现价 vs `position.cost` 接近阈值时，弹窗显示「浮盈 ¥X / X %，AI 建议：减仓 30%」。
- AI 建议输出走单独 prompt（更短、更保守），仅展示，不自动下单。
- 预计：1 天。

## D. 风控 / 可观测

让用户从"信任感"出发，长期使用。

### D.1 AI 命中统计（近 20 次命中率 60%）

- 当前面板已有"AI 命中" chip（命中率 / 平均领先 / 最大偏离），升级为"近 20 次窗口" + 总览两档。
- 配色规则：≥60% 绿 / 40–60% 橙 / <40% 红。
- 预计：半天。

### D.2 通知审计（发过 → 用户动作）

- `SignalEvent` 已有 `kind` / `meta`，新增 `userAction: pending | dismissed | opened | sold` 字段。
- 每次通知被点击 / 忽略 / 用户手动卖出后回写。
- 周报里输出"被忽略最多的价位"清单。
- 预计：1 天。

### D.3 误报率自调（连续忽略 → 收紧阈值）

- 同一 `levelKey` 连续 3 次被用户忽略（无 pendingAction / 无手动操作），自动把该 key 的 `levelLightPct` 收紧 30%。
- 收紧后 30 天内若重新被采纳，恢复原值。
- 预计：半天。

### D.4 健康度面板（成功率 / 耗时 / 失败原因）

- 顶部增加 ⚙ 旁的"诊断"小窗：今日 AI 调用 N 次，成功率 X%，平均耗时 Y ms，最近 3 次失败原因。
- `AIUsageLedger` 已有框架，新增 `failureReason` 字段即可。
- 预计：半天。

## E. 工作流（更顺的操作链路）

让"打开面板 → 看到结论 → 行动"在 5 秒内完成。

### E.1 单标的快捷面板（菜单栏直接看 AI 评级）

- 不展开面板，仅鼠标悬停菜单栏图标：NSPopover 弹小卡，显示 AI 评级 + 关键价位 + 一句话结论。
- 缩短用户"打开面板"的动作。
- 预计：半天。

### E.2 菜单栏轮播命中 AI 提示（图标闪烁）

- 多个自选股轮播：当前轮到"AI 提示"标的时，菜单栏图标闪 2 下。
- 点击直接进入对应自选股面板。
- 预计：1 天。

### E.3 快捷键

- ⌘1/2/3 切 tab（报价 / 复盘 / 设置）
- ⌘R 立即重分析
- ⌘T 草稿委托
- ⌘. 折叠 / 展开面板
- 预计：半天。

### E.4 多窗口（每自选股独立 NSPopover）

- 同时盯多支：每个自选股一个独立菜单栏图标。
- 设置里勾选"启用多窗口模式"。
- 预计：1 天。

## F. 数据 / 接入

### F.1 更多行情源（同花顺 / 雪球 / 东财 WebSocket）

- 当前已有新浪 / 腾讯 / 东财 HTTP，新增 WebSocket 备份（行情延迟 < 200 ms）。
- 自动 failover：主源连续 3 次失败 → 切备份。
- 预计：2–3 天。

### F.2 L2 行情（十档盘口 + 委买委卖）

- 数据源：通达信 L2 / 东财 Level-2（需付费账号）。
- 面板底部加可折叠"盘口"区。
- 预计：1–2 天（含合规评估）。

### F.3 新闻 / 公告接入

- 东方财富 / 同花顺新闻流，按 `code` 聚合。
- AI prompt 注入「近 24h 新闻：…」，作为分析证据。
- 预计：1 天。

### F.4 研报接入（分析师评级）

- 朝阳永续 / 慧博 / 东财研报库，每日增量拉取。
- 评级作为辅助信号：买入 / 增持 → 提示"机构看多"；反之亦然。
- 预计：1–2 天。

## H. 架构演进（前后端分离）

为支撑 §F 数据接入、§G 跨设备、以及本地 LLM / 降级等高级能力，单体 macOS App 必然要从「网络 + 业务 + UI 全栈」拆成「前端 UI + 后端服务」。

完整设计见 [`架构-Rust后端.md`](架构-Rust后端.md)，本节只列要点。

### H.1 为什么必须拆

- 当前 `MarketService.swift`（~600 行）+ `AIService.swift`（~250 行）混了网络 IO / 业务编排 / UI 状态，每次加 §F.1–F.4 都要再嵌更多 HTTP 调用，可维护性递减。
- §G 跨设备（iOS / Watch / Telegram Bot）天然要走 HTTP API，先把后端抽出来省得回头返工。
- §A.3 本地 LLM / §A.3 配套 智能降级 在 Rust 端做更顺手（tokio + tracing + sqlx 都是现成的）。

### H.2 决策（2026-09-18 已敲定）

- **部署模式**：独立服务（NAS / 旧 Mac，监听 `0.0.0.0:8732`）。
- **数据库**：SQLite（rusqlite + sqlx）；想换 PostgreSQL 改连接串即可。
- **迁移节奏**：渐进式 4 阶段（行情 → AI → 数据 → 推送）。

### H.3 模块拆分

```
mojinprince-server/
├── src/
│   ├── main.rs / config.rs / state.rs / error.rs
│   ├── api/           # HTTP 路由（quote / ai / signal / position / settings / ws）
│   ├── service/
│   │   ├── quote/     # sina / tencent / eastmoney / failover
│   │   ├── ai/        # Provider trait / openai / ollama / governor
│   │   └── notify.rs  # WebSocket 推送
│   ├── repo/          # sqlx 数据访问
│   └── model/         # DTO
└── migrations/        # sqlx 迁移
```

### H.4 渐进式路线（每阶段都能回退）

| 阶段 | 范围 | 投入 | 收益 |
| --- | --- | --- | --- |
| 1 | 行情网关（sina/tencent/eastmoney + failover） | 3–4 天 | 前端减少 ~600 行；failover 更稳 |
| 2 | AI 网关（Provider + 用量 + 命中率） | 2 天 | 本地 LLM + 降级天然支持 |
| 3 | 信号 / 持仓 / 设置 落 SQLite + HTTP | 2 天 | 跨设备前置 |
| 4 | WebSocket 推送 + scheduler + §F 数据接入 | 2–3 天 | 实时性 + 数据接入 |
| 5（可选） | 鉴权打开 + iOS / Watch / TG Bot | 3–5 天 | §G 跨设备落地 |

### H.5 关键技术栈

Actix-web 4 + tokio + reqwest + sqlx + tracing + utoipa（Swagger UI）+ JWT。

### H.6 预期收益

- 前端代码减少 ~1100 行（`MarketService` + `AIService` + `SignalTimeline` 落库部分）
- 后端统一处理 failover / 配额 / 成本 / 命中回测，可观测性显著提升
- §A.3 本地 LLM / §F 数据接入 / §G 跨设备 都从"另起炉灶"变成"加一个 service / 加一个 client"

### H.7 关键风险

- 网络抖动 → 前端保留 5 分钟本地缓存（Quote / Signal）
- SQLite 并发 → WAL 模式 + 写串行化
- 公网鉴权漏掉 → 部署时强制 `BIND_ADDR != 0.0.0.0` 必须同时 `JWT_SECRET != ""`

## G. 跨设备

### G.1 iOS 端同步（CloudKit）

- 用 `NSUbiquitousKeyValueStore` 同步 AppSettings（小配置）；
- `CloudKit` 同步 SignalTimeline / 持仓 / 自选（中数据）。
- iOS 端做只读视图（不能下单）。
- 预计：3–5 天（独立 iOS 项目）。

### G.2 Watch 端镜像

- WatchOS App 显示菜单栏报价 + 关键价位（今日三档线）。
- 抬手即看（避免掏出手机）。
- 预计：2–3 天。

### G.3 Telegram Bot

- BotFather 注册 bot，webhook 接 AlertService。
- 关键预警自动转发到 TG；支持 /quote /analyze /holdings 三个命令。
- 预计：1 天。

## 不做什么（保持克制）

- ❌ 自动下单：合规风险 + 用户决策权让渡；继续靠"通知 + 一键跳卖出口袋"。
- ❌ 多账号资产管理 / 跟单：偏离个人工具定位。
- ❌ Web 版 / 移动端：先把 macOS 体验做透（iOS 只读除外）。
- ❌ 第三方数据源再接 N 个：先把 F.1–F.4 吃透。
